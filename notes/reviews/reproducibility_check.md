# Reproducibility check of the report's figures and tables (2026-10-10)

Every row of Appendix C's figure table (`tab:repro-figures`) and every report table computed from runs was
regenerated with the stated command and compared with the committed file. Verdict: **every figure and
table regenerates from the saved outputs, and every report figure drawn from the committed tables is
identical to the committed one** (byte for byte, or pixel for pixel), once four commands are fixed (a
path, an option, an environment variable, a missing link; below). Regenerating the input tables as well
changes two figures by a few pixels: `fig:locality-hessian` (8 pixels) and `fig:optim-gd` (52 pixels).
One committed input does not regenerate: the locality Hessian table `hessians.csv` holds stale rows, which
changes three Hessian exponents of the locality tables and the count "126 of 135" quoted in Sec. 4.4
(finding F1). The figure commands were rerun once more on main `bd3ca51`, after the figure-quality pass
had changed every plotting script and figure: all 22 report figures again regenerate byte-identical.

## Method

- Branch `wip/repro-check` at `8086366` (main when the check started). The two Sec. 4.5 figures were added
  to main later (`d71da92`); they were checked on an export of main (`git archive`) in a scratch directory.
  Main then merged a figure-quality pass (`d3a6d07`: new plotting code and figures, same data); all figure
  commands were rerun on an export of main `bd3ca51` (paragraph after the figures table).
- Windows 11, Git Bash, the project venv (Python 3.13.5, torch 2.14.1, numpy 2.5.3, scipy 1.18.1,
  matplotlib 3.11.2, pandas 3.0.6) in place of `uv run python`, with `PYTHONPATH=.`, one BLAS thread per
  process, at most 8 processes. Library: commit `3a642ef`, `ttn.runner.code_hash()` = `6d786ce7...`.
- Raw data: a junction `data` in the worktree root pointing to `TTN_regimes/data` (read only; removed at
  the end); afterwards no file or directory under `data/` was newer than the start of the check.
- Each stated command was run from the worktree root, writing where it writes (mostly
  `experiments/*/results/`), and its outputs were compared with `HEAD`: PDFs byte for byte (the library's
  `savefig` writes no creation date, so an unchanged figure is byte-identical), otherwise rasterised
  (`pdftoppm`, 72 dpi) and pixel-diffed, plus a `pdftotext` diff; PNGs pixel-diffed (PNG bytes differ after
  re-encoding with this matplotlib/Pillow even when the pixels agree); CSVs numerically (relative and
  absolute differences, CRLF ignored); JSON recursively. The analysis steps that write a figure's input
  tables were also rerun, into scratch directories, wherever they read saved outputs only; sweeps were not
  rerun. All regenerated files were reverted afterwards (`git checkout`): nothing regenerated is committed.

## Findings not fixed (they change committed results or code; for the lead)

- **F1. `experiments/locality/results/hessians.csv` is stale.** `hess_recompute.py` resumes from an existing
  output file and never recomputes rows it has. The committed file has 11,961 rows for 11,781 (run,
  plateau) keys (180 duplicates, multi-component runs, harmless: the last copy is used and matches) and 81
  rows that do not match the final run records. 24 of them (balanced init, mps8 {1,5} at sigma = 0.019,
  0.03 and {2,5} at 0.01, 0.0182) were evaluated at t = 1e9 exactly, the end of a superseded shorter
  trajectory, instead of at the record's plateau midpoint (1e10 to 3e13): lambda_min about 1e-13 to 1e-10
  instead of 1e-8 to 1e-5. The other 57 (seven fan-in or balanced MPS cases) have midpoints within 0.7%
  and lambda_min within 2.7% of the regenerated ones. `finalize.sh` into a fresh directory
  recomputes every row, so the documented command does not give the committed tables:
  `twocomp_balanced_table`: mps8 {2,5} lambda_min at the smallest sigma -3.5e-13 -> -1.1e-5 and x = 8.90 ->
  2.01; mps8 {1,5} -4.2e-10 -> -1.4e-6, x = 6.22 -> 3.49; `extensions_table`, balanced mps8 {1,5}: x = -5.42
  -> 3.24; `twocomp`, `twocomp_chi4`, `robust` tables: Hessian columns within 1e-4 (Markdown tables
  identical). Effect on the text (Sec. 4.4, saddle type; `notes/locality.md` 7-10, README): "x within 0.2
  of k - 2 in 126 of 135 rows with k = 3-5" becomes **127 of 135** (k = 4: 37 of 38); the quoted ranges
  1.64-2.16 (k = 4) and 2.82-3.76 (k = 5) then hold without exclusions; "raw x within 0.2 of p in 95% of 169
  rows" is 161 of 171 (94.2%) with the committed tables and 164 of 171 (95.9%) with the regenerated ones
  in my count, so the 169-row set is slightly different. `notes/locality.md` explains x = 8.9, 6.2 and -5.4
  as artefacts of a sign-correction phase and of pinned states at t = 1e9; they are Hessians at the end of
  superseded trajectories. Suggested: rerun `finalize.sh experiments/locality/results` (with the link of
  fix 4), update the count in the report and the note, and make the resume of `hess_recompute.py` key on
  the record's `t_mid` (or drop it).
- **F2. Locality steps are tied to the remote layout.** The run records store
  `"traj": "/root/outputs/locality/traj/..."`. On main, `plot_trees.py` and `plot_bonds.py` now fall back to
  `$LOCALITY_OUT/traj` (figure-quality pass), but `hess_recompute.py`, `growth.py`, `route_amps.py`,
  `levels.py`, `bond_events2.py` and `r12.py` still open the stored path, so `LOCALITY_OUT` is not enough
  for `finalize.sh`. Without a link `hess_recompute.py` prints "0 plateau Hessians", writes an empty file
  and exits 0, `make_figures.py` then fails (`EmptyDataError`), and `finalize.sh` prints "done" because its
  `py()` wrapper ends in `|| true`. I ran `finalize.sh` (at `8086366`) with a `numpy.load` shim in the
  scratch directory that maps `/root/outputs/` to `data/` (equivalent to the link; no repository change).
  Code fix suggested: the same fallback in `analysis.load_records` (it serves every step), and let `py()`
  fail on a non-zero exit.
- **F3. Order of rows.** Several per-run tables are written in file-listing or pool order, which differs
  between machines (`centred_chi9_gf.csv`, `sgd_runs.csv`, `order_independent_seeds.csv`,
  `bond_events2_*.csv`, `bond_profiles_multicomp.csv`, `hessians.csv`): content identical, order not.
- **F4. Platform-dependent numbers that do not reach the report.** `optim_samples/map1d.py` iterates
  chaotic maps for 2000 steps, so the attractor points and statistics for h/h_c > 1.3 depend on
  floating-point details (`map1d_points.csv`: 192,418 points here, 192,914 committed); the report figure
  drawn from them differs in 52 pixels inside a filled chaotic band. Bootstrap s.e. of two unquoted
  `sigma_fits.csv` entries (order) and a few L-BFGS levels (data_teacher, 1.4e-4) differ slightly.
- **F5. Cosmetic.** `hess_main.csv` keeps the old `order` format; PNGs are re-encoded (pixel-identical);
  `scaling_b4_exponents.csv` writes roundoff zeros as "-0.00" or "0.00".

## What was not regenerated, and why

- **Raw outputs** (`data/<experiment>/`): written by the sweeps, which were not rerun (task rule); each
  experiment README gives the sweep commands. Nothing the report needs is missing from the local copies.
- **Tables written by a sweep script itself**, read here in their committed form (their consumers were
  regenerated from them): `s2s_core/results/lo_d.csv`, `lo_chi.csv`, `lo_K.csv` (`lo_sweep.py`, input of
  `fig:s2s-prefactor`) and `aligned.csv` (`aligned.py`, `fig:s2s-aligned`); `optim_samples/results/p9_sgd.csv`
  (`p9_sgd.py`, `fig:optim-sgd`); `order/results/h1b_saddle_*.csv` (written by the `h1b.py` sweep,
  `fig:order-wrong`; `rebuild_h1b_csv.py` only approximates them from the trajectories, by design).
- **`data_teacher/results/r2_saddle_cores.pt`**: the stored exact saddles are reused by design (README: a
  fresh computation can pick another gauge copy on another platform and shift per-run times); the Hessian
  tables computed from them regenerate.
